# Errors

Every method returns `erlc::Result<T>`, an alias for `Result<T, erlc::Error>`. Error
messages never contain your server key or global key.

## `Error` variants

| Variant | Meaning | Typical action |
|---|---|---|
| `Api(ApiError)` | The API answered with an error status (not 429) | Check `code()` and the helpers below |
| `RateLimited(RateLimited)` | Too many requests | Wait `retry_after()`; never retry in a tight loop |
| `Transport(TransportError)` | No response: connection failure, timeout, TLS | Retry reads later; see [Commands](commands.md) for timeouts |
| `Decode(DecodeError)` | Success status, but the body did not match the models | Report it as a bug with the redacted body |
| `InvalidInput(&str)` | Bad input caught before sending | Fix the input |

`Error` is `#[non_exhaustive]`, so always include a `_` or `e` arm when matching.

```rust,no_run
use erlc::Error;

async fn describe(client: &erlc::Client) {
    match client.server_info().await {
        Ok(info) => println!("{}", info.name),
        Err(Error::Api(e)) if e.is_auth() => eprintln!("key rejected: {e}"),
        Err(Error::Api(e)) if e.is_module_outdated() => eprintln!("kick all players and retry"),
        Err(Error::RateLimited(e)) => eprintln!("rate limited for {:?}", e.retry_after()),
        Err(Error::Transport(e)) if e.is_timeout() => eprintln!("timed out"),
        Err(e) => eprintln!("{e}"),
    }
}
```

`Error` implements `std::error::Error`, so it works with `?`, `Box<dyn Error>`, `anyhow`
and `eyre`. The underlying cause (for example the JSON or network error) is available
through `source()`.

## `ApiError`

| Method | Returns |
|---|---|
| `status()` | HTTP status code |
| `code()` | `Option<ErrorCode>` |
| `raw_code()` | `Option<i64>`, the number as sent |
| `message()` | Message from the response body |
| `command_id()` | Command execution ID, on some command errors |
| `bucket()` | `X-RateLimit-Bucket` header, if sent |
| `body()` | Raw body, truncated to 4 KiB |
| `is_auth()` | Codes 2000-2005 and 4000, or HTTP 401/403 |
| `is_server_offline()` | Code 3002 or HTTP 422 |
| `is_module_outdated()` | Code 9999 |

## ER:LC error codes

`ErrorCode` covers every code in the [official reference](https://apidocs.erlc.gg/error-codes).
Unknown codes become `ErrorCode::Other(n)`.

| Code | Variant | Meaning | What to do |
|---|---|---|---|
| 0 | `UnknownError` | Unknown error | Retry later; open an API ticket if it persists |
| 1001 | `RobloxCommunication` | Could not reach Roblox or the server | Retry later |
| 1002 | `InternalError` | Internal ER:LC error | Retry later |
| 2000 | `MissingServerKey` | No server key sent | Should not happen with this crate |
| 2001 | `MalformedServerKey` | Key is malformed | Check you copied the whole key |
| 2002 | `InvalidServerKey` | Key invalid or expired | The owner may have regenerated it |
| 2003 | `InvalidGlobalKey` | Global key invalid | Check or regenerate your app key |
| 2004 | `BannedServerKey` | Key banned from the API | Contact ER:LC support |
| 2005 | `UnauthenticatedMultiServer` | Multiple servers without a global key | Use a [global key](public-apps.md) |
| 3001 | `InvalidCommand` | No valid command in the request | Check the command text |
| 3002 | `ServerOffline` | Server has no players | Wait until someone joins |
| 4000 | `Unauthorized` | Not allowed on this server | Check permissions / authorization link |
| 4001 | `RateLimited` | Rate limited or blocked | See [Rate limits](rate-limits.md) |
| 4002 | `RestrictedCommand` | Command is restricted | Use a different command |
| 4003 | `ProhibitedMessage` | Message is prohibited | Change the message |
| 9998 | `RestrictedResource` | Resource is restricted | Not available to your key |
| 9999 | `OutdatedModule` | In-game module out of date | Kick all players from the server and retry |

`code.description()` returns the meaning as text, and `code.as_i64()` the number.

## `RateLimited`

| Method | Returns |
|---|---|
| `retry_after()` | How long to wait |
| `bucket()` | Bucket hit, e.g. `"global"` or `"command"` |
| `message()` | Message from the API, if any |
| `is_local()` | `true` if the client blocked the request without sending it |

## `TransportError`

`is_timeout()` and `is_connect()` tell the common cases apart. For commands, a timeout
means the outcome is unknown.

## `DecodeError`

The API returned success, but the body did not match the expected shape. `status()` and
`body()` (truncated, may contain server data) help diagnose it. Please
[open an issue](https://github.com/ERLC-Rust/erlc.rs/issues) with a redacted body.

## Repeated failures

The API temporarily blocks clients that keep sending requests that fail with 400, 401, 403
or 404. If a key keeps returning `is_auth()` errors, stop using it: it has most likely been
regenerated by the server owner.
